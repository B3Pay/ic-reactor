This example renders canister return values — records, variants, vectors,
tuples, recursive types and func references — from the metadata
`ResultFieldVisitor` builds for a service's return types. Its `ResultRenderer`
also has components for blobs and optionals, which the sample values do not
reach. It works on a local IDL and sample values, so it needs no canister.

## Features Demonstrated

- **Result Metadata**: `ResultFieldVisitor.visitService` builds one
  `MethodMeta` per method.
- **Resolution**: `resolve()` turns a raw Candid value into display-ready
  nodes.
- **Recursive Types**: a `Category` that contains itself renders level by level.
- **Func References**: an ICRC ledger's archived-block callbacks render as
  canister and method.

## Implementation

```tsx
// src/App.tsx
import { ResultFieldVisitor } from "@ic-reactor/candid"
import { IDL } from "@icp-sdk/core/candid"

const visitor = new ResultFieldVisitor()
const serviceMeta = visitor.visitService(testIDL({ IDL }))

// Metadata for one method, resolved against a raw Candid value
const resolved = serviceMeta["get_user"].resolve(mockUser)

// One node per return value, each carrying its display value
return resolved.results.map((result, i) => (
  <ResultRenderer key={i} result={result} />
))
```

<Aside type="note">
  Unwrapping a canister's `Result` variant is a different feature: a reactor
  returns the `Ok` value and throws a `CanisterError` for `Err`. See
  [Queries](/v3/framework/queries).
</Aside>
