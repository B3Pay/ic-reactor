`useReactorInfiniteQuery` is a React hook for paginated data fetching using a `Reactor` instance.

## Import

```typescript
import { useReactorInfiniteQuery } from "@ic-reactor/react"
```

## Usage

```tsx
import { useReactorInfiniteQuery } from "@ic-reactor/react"
import { backend } from "./reactor"

function Feed() {
  const { data, fetchNextPage, hasNextPage } = useReactorInfiniteQuery({
    reactor: backend, // 👈 Required
    functionName: "getPosts",
    getArgs: (pageParam) => [{ cursor: pageParam, limit: 20 }] as const,
    initialPageParam: null as string | null,
    getNextPageParam: (lastPage, allPages) => lastPage.nextCursor,
  })

  return (
    <div>
      {data?.pages.map((page) => (
        // Render posts
        <div key={page.id}>{/*...*/}</div>
      ))}
      <button onClick={() => fetchNextPage()} disabled={!hasNextPage}>
        Load More
      </button>
    </div>
  )
}
```

## Options

### Required Options

| Option             | Type                               | Description                                                         |
| ------------------ | ---------------------------------- | ------------------------------------------------------------------- |
| `reactor`          | `Reactor<A, T>`                    | The Reactor instance to use                                         |
| `functionName`     | `string`                           | The canister method to call                                         |
| `getArgs`          | `(pageParam) => Args \| skipToken` | Builds the call arguments for each page; `skipToken` waits for them |
| `initialPageParam` | `TPageParam`                       | Page param the first fetch starts from                              |
| `getNextPageParam` | `function`                         | Function to determine the next page param (cursor/index)            |

<Aside type="caution">
  There is no `args` option on this hook — arguments come from `getArgs`, which
  is called for every page. `getArgs` and `initialPageParam` are both required.
</Aside>

### Optional Options

Same as [useActorInfiniteQuery](/v3/reference/createactorhooks/useactorinfinitequery).

## Notes

<Aside type="caution">
  An update method passed here runs on the canister again on every refetch
  (mount, window focus, reconnect, invalidation) and retry, each time as a new
  call. Use it only for an update method that is safe to repeat, and use
  `useReactorMutation` or `useReactorMethod` for a method that changes state.
  With no `retry` hook option set, an update method retries only a
  `SysTransient` rejection, which proves the call never ran. See [Update Methods
  in Queries](/v3/framework/queries#update-methods-in-queries).
</Aside>
