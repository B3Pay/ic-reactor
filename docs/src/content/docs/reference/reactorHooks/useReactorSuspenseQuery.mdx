`useReactorSuspenseQuery` is a React hook for fetching data via a `Reactor` instance with Suspense support.

## Import

```typescript
import { useReactorSuspenseQuery } from "@ic-reactor/react"
```

## Usage

```tsx
import { Suspense } from "react"
import { useReactorSuspenseQuery } from "@ic-reactor/react"
import { backend } from "./reactor"

function UserProfile({ userId }) {
  const { data } = useReactorSuspenseQuery({
    reactor: backend, // 👈 Required
    functionName: "getUser",
    args: [userId],
  })

  // data is always defined
  return <div>{data.name}</div>
}

function App() {
  return (
    <Suspense fallback="Loading...">
      <UserProfile userId="123" />
    </Suspense>
  )
}
```

## Options

### Required Options

| Option         | Type            | Description                 |
| -------------- | --------------- | --------------------------- |
| `reactor`      | `Reactor<A, T>` | The Reactor instance to use |
| `functionName` | `string`        | The canister method to call |

### Optional Options

Same as [useActorSuspenseQuery](/v3/reference/createactorhooks/useactorsuspensequery).

<Aside type="caution">
  Like `useActorSuspenseQuery`, this hook does **NOT** support the `enabled`
  option.
</Aside>

## Return Value

Returns a Suspense-enabled Query result object. `data` is always defined. A
failed first load is thrown to the nearest Error Boundary; a failed refetch
keeps `data` and sets `status: "error"` and `error` instead.

## Notes

<Aside type="caution">
  An update method passed here runs on the canister again on every refetch
  (mount, window focus, reconnect, invalidation) and retry, each time as a new
  call. Use it only for an update method that is safe to repeat, and use
  `useReactorMutation` or `useReactorMethod` for a method that changes state.
  With no `retry` hook option set, an update method retries only a
  `SysTransient` rejection, which proves the call never ran. See [Update Methods
  in Queries](/v3/framework/queries#update-methods-in-queries).
</Aside>
