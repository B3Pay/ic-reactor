`useActorQuery` is a React hook for fetching data from Internet Computer canisters. It wraps TanStack Query's `useQuery` with canister-specific functionality.

## Import

```typescript
import { createActorHooks } from "@ic-reactor/react"

const { useActorQuery } = createActorHooks(backend)
```

<Aside type="tip">
  It is recommended to rename the hooks to reflect the canister name, especially when working with multiple canisters:

```typescript
const { useActorQuery: useBackendQuery } = createActorHooks(backend)
```

</Aside>

## Usage

```tsx
function UserProfile({ userId }: { userId: string }) {
  const { data, isPending, error } = useActorQuery({
    functionName: "getUser",
    args: [userId],
  })

  if (isPending) return <div>Loading...</div>
  if (error) return <div>Error: {error.message}</div>

  return <div>{data?.name}</div>
}
```

## Options

`UseActorQueryParameters` extends react-query's `QueryObserverOptions`, giving you access to all standard react-query options plus our custom actor options.

### Required Options

| Option         | Type     | Description                 |
| -------------- | -------- | --------------------------- |
| `functionName` | `string` | The canister method to call |

### Optional Options

| Option                 | Type                            | Default       | Description                                                                      |
| ---------------------- | ------------------------------- | ------------- | -------------------------------------------------------------------------------- |
| `args`                 | `array \| skipToken`            | `[]`          | Arguments to pass to the method, or `skipToken` while they are not known         |
| `enabled`              | `boolean`                       | `true`        | Whether the query should run                                                     |
| `staleTime`            | `number`                        | `0`           | Time in ms before data is considered stale                                       |
| `gcTime`               | `number`                        | `300000`      | Time in ms before unused data is garbage collected                               |
| `refetchInterval`      | `number \| false`               | `false`       | Polling interval in ms                                                           |
| `refetchOnWindowFocus` | `boolean`                       | `true`        | Refetch when window regains focus                                                |
| `refetchOnMount`       | `boolean`                       | `true`        | Refetch when component mounts                                                    |
| `refetchOnReconnect`   | `boolean`                       | `true`        | Refetch when network reconnects                                                  |
| `retry`                | `number \| boolean \| function` | QueryClient's | Retry policy ([update methods](/v3/framework/queries#update-methods-in-queries)) |
| `retryDelay`           | `number \| function`            | exponential   | Delay between retries                                                            |
| `select`               | `function`                      | -             | Transform the data before returning                                              |
| `queryKey`             | `array`                         | -             | Additional query key segments                                                    |
| `callConfig`           | `CallConfig`                    | -             | IC agent call configuration                                                      |

## Return Value

Returns a TanStack Query result object:

| Property        | Type                                | Description                             |
| --------------- | ----------------------------------- | --------------------------------------- |
| `data`          | `TData \| undefined`                | The resolved data                       |
| `error`         | `Error \| null`                     | Error if query failed                   |
| `status`        | `'pending' \| 'error' \| 'success'` | Query status                            |
| `isPending`     | `boolean`                           | True if no data yet                     |
| `isError`       | `boolean`                           | True if query errored                   |
| `isSuccess`     | `boolean`                           | True if query succeeded                 |
| `isFetching`    | `boolean`                           | True if fetching (including background) |
| `isRefetching`  | `boolean`                           | True if refetching                      |
| `refetch`       | `function`                          | Manually trigger a refetch              |
| `dataUpdatedAt` | `number`                            | Timestamp of last data update           |

## Examples

### Basic Query

```tsx
const { data, isPending, error } = useActorQuery({
  functionName: "greet",
  args: ["World"],
})
```

### Waiting for Args

When the arguments are not known yet, pass TanStack Query's `skipToken`
(re-exported by `@ic-reactor/react`) in their place. The query waits without
calling the canister, and fetches as soon as `args` holds real arguments:

```tsx
import { skipToken } from "@ic-reactor/react"

function UserProfile({ userId }: { userId: string | undefined }) {
  const { data } = useActorQuery({
    functionName: "getUser",
    // No `userId!`, no placeholder id, no `enabled`
    args: userId ? [userId] : skipToken,
  })
}
```

A skipped query has a cache entry of its own under its method's key (at the
canister `callConfig` names), which no call's key shares: it shows no data
until its arguments arrive, not even that of a query of the method made
without arguments. `refetch()` has nothing to run until then, and TanStack
Query answers it with a "Missing queryFn" error, so offer a refresh only once
the arguments exist.

### Conditional Query

Use `enabled` when the arguments are known but the query should still wait,
for a reason of your own:

```tsx
const { isAuthenticated } = useAuth()

const { data } = useActorQuery({
  functionName: "getUser",
  args: [userId],
  enabled: isAuthenticated, // Only fetch once signed in
})
```

### With Select

```tsx
// Extract only the name from the user object
const { data: userName } = useActorQuery({
  functionName: "getUser",
  args: [userId],
  select: (user) => user?.name,
})
```

### Stale Time Configuration

```tsx
// Data stays fresh for 5 minutes
const { data } = useActorQuery({
  functionName: "getConfig",
  args: [],
  staleTime: 5 * 60 * 1000,
})

// Data is never stale
const { data } = useActorQuery({
  functionName: "getMetadata",
  args: [],
  staleTime: Infinity,
})
```

### Polling

```tsx
// Refetch every 10 seconds
const { data } = useActorQuery({
  functionName: "getPrice",
  args: [],
  refetchInterval: 10_000,
})
```

### Manual Refetch

```tsx
const { data, refetch, isFetching } = useActorQuery({
  functionName: "getNotifications",
  args: [],
})

return (
  <div>
    <NotificationList data={data} />
    <button onClick={() => refetch()} disabled={isFetching}>
      Refresh
    </button>
  </div>
)
```

### Error Handling

```tsx
import { CanisterError, CallError } from "@ic-reactor/react"

const { data, error, isError } = useActorQuery({
  functionName: "getBalance",
  args: [principal],
})

if (isError) {
  if (error instanceof CanisterError) {
    // Business logic error from canister
    return (
      <div>
        Canister error [{error.code}]: {JSON.stringify(error.err)}
      </div>
    )
  }
  // Network or other error
  return <div>Error: {error.message}</div>
}
```

### Type-Safe Queries

```tsx
// TypeScript infers types from your canister interface
const { data } = useActorQuery({
  functionName: "getUser", // ✅ Autocompletes valid methods
  args: ["user-123"], // ✅ Type-checked
})
// data is typed as User | undefined
```

### With Custom Query Key

```tsx
// Add custom segments to the query key
const { data } = useActorQuery({
  functionName: "getData",
  args: [],
  queryKey: ["version", "2"],
})
// Full key: [canisterId, "getData", "[]", "version", "2"]
```

The args segment is the JSON-serialized `args` array, so an empty `args: []`
still contributes the literal `"[]"`. Custom `queryKey` segments are appended
after it, never in place of the identity prefix.

### Dependent Queries

```tsx
import { skipToken } from "@ic-reactor/react"

function UserPosts({ userId }: { userId: string }) {
  // First query
  const { data: user } = useActorQuery({
    functionName: "getUser",
    args: [userId],
  })

  // Dependent query - waits until the first one has the user's id
  const { data: posts } = useActorQuery({
    functionName: "getUserPosts",
    args: user ? [user.id] : skipToken,
  })

  return <PostList posts={posts} />
}
```

## Type Parameters

```typescript
useActorQuery<
  M extends FunctionName<A>,  // Method name
  TSelected = ReturnType       // Type after select
>(options: UseActorQueryParameters<A, M, T, TSelected>)
```

The types are automatically inferred from your actor interface, so you typically don't need to specify them manually.

## Notes

<Aside type="caution">
  An update method passed here runs on the canister again on every refetch
  (mount, window focus, reconnect, invalidation) and retry, each time as a new
  call. Use it only for an update method that is safe to repeat, and use
  `useActorMutation` or `useActorMethod` for a method that changes state. With
  no `retry` hook option set, an update method retries only a `SysTransient`
  rejection, which proves the call never ran. See [Update Methods in
  Queries](/v3/framework/queries#update-methods-in-queries).
</Aside>

<Aside type="note">
  The query key is automatically generated as `[canisterId, functionName,
  argKey, ...queryKey]`. `argKey` is the arguments serialized as one JSON
  string, with BigInt values as decimal strings and plain-object keys sorted,
  so queries with different arguments are cached separately. A `DisplayReactor`
  adds a `{ transform: "display" }` segment after `functionName`, an
  `{ agent }` segment follows when `callConfig.agent` is not the
  `ClientManager`'s own agent, and an `{ effectiveTarget }` segment follows
  when `callConfig` targets a different canister or subnet. See
  [generateQueryKey](/v3/reference/reactor#generatequerykey) for the full shape.
</Aside>

<Aside type="note">
  `skipToken` works in `useActorQuery` and `useActorInfiniteQuery` (as
  `getArgs`). The suspense hooks do not take it: TanStack Query cannot suspend
  on a query that has nothing to run. Render the suspense query in a component
  that only mounts once the arguments exist.
</Aside>

<Aside type="tip">
  When using `select`, the selected data is what gets passed to your component.
  The original query data is still cached and used for determining staleness.
</Aside>
